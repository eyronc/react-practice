01 useState — All the Ways to Use It hook ▼

useState lets React remember a value between renders. Every time you call the setter, React re-renders the component with the new value. Here are all the ways you'll see it written.

// The most basic form — you might see this first
import { useState } from 'react';

function Counter() {
  // useState returns an array: [currentValue, setterFunction]
  const countState = useState(0);
  const count = countState[0];
  const setCount = countState[1];

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}
// Type 2 — Array destructuring (the standard way everyone writes it)
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={() => setCount(count - 1)}>-</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
// Type 3 — Lazy initializer (for expensive initial values)
function getInitialCount() {
  return parseInt(localStorage.getItem('count')) || 0;
}

function Counter() {
  // Pass a FUNCTION, not a value — React only calls it once
  const [count, setCount] = useState(getInitialCount);
  //                                     ↑ no () here!
  return <p>Count: {count}</p>;
}
⚡ Why this matters

If you write useState(getInitialCount()) with parentheses, the function runs on EVERY render. Without parentheses, React only runs it once on mount.

// Type 4 — Object state (group related values together)
function UserForm() {
  const [user, setUser] = useState({ name: '', age: 0, city: '' });

  // CRITICAL: Always spread the old state when updating object state
  const updateName = (e) => {
    setUser({ ...user, name: e.target.value });
  };

  return (
    <div>
      <input value={user.name} onChange={updateName} />
      <p>Hello, {user.name || 'stranger'}!</p>
    </div>
  );
}
🧪 Experiment
  • Start with Type 2 (destructuring) — it's the standard. Get comfortable with it first.
  • Try calling setCount(count + 1) three times in a row. Does count go up by 3? (It won't. Learn why.)
  • Try setting state to the same value twice. Does React re-render? Check with a console.log.
02 The Functional Updater — setState(prev => ...) hook ▼

There are two ways to update state. The version you already know, and a safer version that uses the previous value. This matters more than it looks.

❌ Direct update (can be stale)

setCount(count + 1);
setCount(count + 1); // still +1, not +2!

✅ Functional updater (always safe)

setCount(prev => prev + 1);
setCount(prev => prev + 1); // correctly +2!
// Real example — toggle
const [isOn, setIsOn] = useState(false);

// Type A — direct
<button onClick={() => setIsOn(!isOn)}>Toggle</button>

// Type B — functional (preferred)
<button onClick={() => setIsOn(prev => !prev)}>Toggle</button>
💡 Rule of thumb

If your new state depends on the old state, always use prev => .... If it's a totally new value (like from an input), you can set directly.

🧪 Experiment
  • Make a button that calls setCount(count + 1) three times. What happens?
  • Now make it call setCount(prev => prev + 1) three times. What happens now?
  • This is called "state batching." You just discovered one of React's most common bugs.
03 Event Handlers — All the Ways to Write Them event ▼

React uses camelCase event names. You pass a function, never a function call. Here are all the styles you'll encounter.

<button onClick={() => setCount(count + 1)}>Click</button>
<input onChange={(e) => setValue(e.target.value)} />
const handleClick = () => {
  setCount(prev => prev + 1);
  console.log('clicked!');
};

// Pass the function REFERENCE — no () at the end!
return <button onClick={handleClick}>Click</button>;
const handleChange = (e) => {
  setValue(e.target.value);    // what user typed
  e.preventDefault();           // stop default behavior
  e.stopPropagation();          // stop event bubbling
};
const handleSelect = (id) => setSelected(id);

// Wrap in arrow so it doesn't auto-call on render
<button onClick={() => handleSelect(1)}>Select 1</button>
⚡ Common Mistake

onClick={handleSelect(1)} calls it immediately on render. Always wrap: onClick={() => handleSelect(1)}

🧪 Experiment
  • Try onClick={handleClick()} with parentheses. Notice it fires on render, not on click.
  • Add console.log(e) inside onChange. Explore the event object's properties.
  • Try onDoubleClick, onMouseEnter, onKeyDown.
04 Controlled Inputs — React Owns the Value pattern ▼

In React, form inputs should be "controlled" — React state drives the value, not the DOM.

❌ Uncontrolled

<input type="text" /> // React doesn't know

✅ Controlled

const [name, setName] = useState('');
<input value={name} onChange={(e) => setName(e.target.value)} />
// All controlled input types
// Text
<input value={text} onChange={(e) => setText(e.target.value)} />

// Checkbox — use e.target.checked
<input type="checkbox" checked={checked}
  onChange={(e) => setChecked(e.target.checked)} />

// Select dropdown
<select value={selected} onChange={(e) => setSelected(e.target.value)}>
  <option value="a">A</option>
</select>

// Textarea
<textarea value={area} onChange={(e) => setArea(e.target.value)} />
🧪 Experiment
  • Add a <p> below each input that mirrors what you type in real-time.
  • Remove onChange but keep value={text}. Try typing. What happens and why?
  • Make an input that only allows numbers: onChange={(e) => setVal(e.target.value.replace(/\D/g, ''))}
05 Conditional Rendering — Show & Hide Things concept ▼

Show different UI based on state. Four patterns — each has a use case.

// Show one thing OR another
{isLoggedIn ? <p>Welcome!</p> : <p>Please log in.</p>}
<h1>{isLoggedIn ? 'Dashboard' : 'Login'}</h1>
// Show something OR nothing
{hasError && <p>Something went wrong!</p>}

// ⚠️ 0 && renders "0" — fix: use count > 0
{count > 0 && <p>Items: {count}</p>}
function UserProfile({ user }) {
  if (!user) return <p>Loading...</p>;
  if (user.banned) return <p>Suspended.</p>;
  return <h1>Hello, {user.name}!</h1>;
}
let badge;
if (status === 'active')  badge = <span>🟢 Active</span>;
if (status === 'pending') badge = <span>🟡 Pending</span>;
if (status === 'banned')  badge = <span>🔴 Banned</span>;
return <div>Status: {badge}</div>;
🧪 Experiment
  • Build a toggle button that shows/hides a message using ternary, then rewrite with &&.
  • Try the 0 && bug intentionally. Set count to 0 and watch "0" appear in your UI.
  • Build a StatusBadge component using the variable method with all 3 statuses.
06 Array State — Add, Remove, Update Items hook ▼

When state is an array, you never mutate it directly. Always create a new array.

const [items, setItems] = useState(['Apple', 'Banana']);

// ➕ ADD
setItems([...items, 'Cherry']);

// ➖ REMOVE
setItems(items.filter((_, i) => i !== indexToRemove));

// ✏️ UPDATE
setItems(items.map((item, i) => i === index ? newValue : item));

❌ Mutating (no re-render)

items.push('Cherry');  // BAD
setItems(items);       // same ref!

✅ New array (re-renders)

setItems([...items, 'Cherry']); // GOOD
🧪 Experiment
  • Build a todo list: input + add button + list of todos, each with a delete button.
  • Try items.push('x'); setItems(items) — confirm it doesn't re-render. Then fix it.
  • Add a "mark done" feature that toggles a done property on each todo object.
07 Lifting State Up — Sharing Between Components pattern ▼

When two sibling components need the same data, move state UP to their closest common parent.

❌ Problem — isolated state, siblings can't share
function Search() {
  const [query, setQuery] = useState(''); // isolated!
  return <input onChange={(e) => setQuery(e.target.value)} />;
}
function Results() {
  return <p>No access to query here</p>; // 😢
}
✅ Lifted — parent owns state, passes down
function App() {
  const [query, setQuery] = useState('');
  return (
    <>
      <Search query={query} onSearch={setQuery} />
      <Results query={query} />
    </>
  );
}

  • The search state lives in App. Pass it down to both the input and the list.
  • Add a subject filter dropdown alongside the search.
08 Derived State — Compute, Don't Store concept ▼

If a value can be calculated from existing state, just calculate it during render. Storing it in state creates sync bugs.

❌ Redundant state

const [items, setItems] = useState([]);
const [count, setCount] = useState(0); // 👎 easy to forget to sync

✅ Derived (always in sync)

const [items, setItems] = useState([]);
const count = items.length; // 👍 auto-updates
// Practical example
const filtered = students.filter(s =>
  s.name.toLowerCase().includes(query.toLowerCase())
);
const average = filtered.reduce((sum, s) => sum + s.grade, 0) / filtered.length || 0;
💡 The Rule

Ask: "Can I compute this from existing state?" If yes — don't store it. Just calculate it in the render.

🧪 Experiment
  • Add a live grade average to your Student Directory that updates as you search/filter.
  • Add a "highest grade" display — derived from filtered list, not stored separately.
  • Try storing the filtered list in state (wrong way). See how it gets out of sync.
