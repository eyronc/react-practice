01 What is React & Why JSX? concept ▼

React is a JavaScript library for building user interfaces. JSX is just a shorthand — your browser never sees JSX. Babel transforms it into plain React.createElement() calls behind the scenes.

// JSX (what you write)
const element = <h1>Hello, World!</h1>;
// What Babel turns it into
const element = React.createElement(
  'h1',
  null,
  'Hello, World!'
);
🧪 Experiment
  • Open the browser console on any page and think: what would React.createElement actually return?
  • JSX is NOT HTML. It compiles to JavaScript. Remember this every time you write it.
  • Google "Babel REPL" and paste some JSX. Watch it transform live.

Vite is the fastest way to spin up a React project. It's much faster than the old Create React App. Run these commands in your terminal:

03 Your First Component core ▼

A component is just a JavaScript function that returns JSX. The function name MUST start with a capital letter — this is how React tells the difference between HTML tags and your custom components.

// src/App.jsx — delete everything, write this from scratch
function App() {
  return (
    <div>
      <h1>My First React App</h1>
      <p>Hello from a component!</p>
    </div>
  );
}

export default App;
🧪 Experiment
  • Rename App to app (lowercase). See the error. Capital letter = required.
  • Remove the export default line. See what breaks.
  • Create a second function called Header in the same file and use it inside App like <Header />.
04 JSX Rules — The Gotchas rules ▼

JSX looks like HTML but has strict rules. Deliberately break each rule below, read the error, then fix it. You'll never forget them.

❌ BROKEN — Two root elements (try this, read the error)
return (
  <h1>Title</h1>
  <p>Paragraph</p>  // Error: Adjacent JSX elements
);
✅ FIXED — Use a fragment
return (
  <>
    <h1>Title</h1>
    <p>Paragraph</p>
  </>
);
❌ BROKEN — Using class instead of className
<div class="container">  // Warning: use className
✅ FIXED
<div className="container">
❌ BROKEN — Unclosed self-closing tags
<img src="photo.jpg">   // Error in JSX
<input type="text">     // Error in JSX
✅ FIXED — Self-close all void elements
<img src="photo.jpg" />
<input type="text" />
🧪 Experiment
  • Also try: for attribute on a label → should be htmlFor
  • Try: onclick → should be onClick (camelCase everything)
  • Every error message tells you exactly what's wrong. Read them carefully.
05 Dynamic Data with { } core ▼

Curly braces { } are your escape hatch from JSX back into JavaScript. Anything that evaluates to a value can go inside them.

// Types of expressions you can use in { }
function App() {
  const name = "Maria";
  const age = 22;
  const greet = () => "Hello!";
  const isStudent = true;

  return (
    <div>
      <p>Name: {name}</p>
      <p>Age: {age}</p>
      <p>Math: {age * 2}</p>
      <p>Fn: {greet()}</p>
      <p>Role: {isStudent ? "Student" : "Other"}</p>
    </div>
  );
}
🧪 Experiment
  • Try putting an if statement inside { }. See why it fails. (Statements ≠ expressions)
  • Try rendering {true}, {false}, {null} — what shows up? Why?
  • Try rendering an object: {{ name: "hi" }}. Read the error.
  • Render today's date: {new Date().toLocaleDateString()}
06 Props — Passing Data to Components core ▼

Props are how you pass data from a parent component to a child. They make components reusable. Think of them like arguments to a function — because that's exactly what they are.

// Create a reusable UserCard component
function UserCard({ name, age, city }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>Age: {age}</p>
      <p>City: {city}</p>
    </div>
  );
}

function App() {
  return (
    <>
      <UserCard name="Ana" age={24} city="Manila" />
      <UserCard name="Ben" age={30} city="Cebu" />
    </>
  );
}
🧪 Experiment
  • Remove one prop (e.g. don't pass city). What renders? How do you handle missing props with a default?
  • Add a default: function UserCard({ name, city = "Unknown" })
  • Try passing a non-string prop: age={25} vs age="25". Are they different?
  • Can you pass a function as a prop? Try it.
07 Rendering Lists with .map() core ▼

To render a list, use JavaScript's .map() to transform an array of data into an array of JSX elements. React requires a unique key prop on each item so it can track changes efficiently.

// Array of data → array of JSX
const students = [
  { id: 1, name: "Ana", grade: "A" },
  { id: 2, name: "Ben", grade: "B+" },
  { id: 3, name: "Cara", grade: "A-" },
];

function App() {
  return (
    <ul>
      {students.map((student) => (
        <li key={student.id}>
          {student.name} — {student.grade}
        </li>
      ))}
    </ul>
  );
}
🧪 Experiment
  • Remove the key prop. Read the warning. Now add it back.
  • Use the array index as key: key={index}. It works but why is it bad?
  • Replace <li> with your UserCard component from Lesson 6. Combine both lessons!
  • Try filtering before mapping: students.filter(s => s.grade === "A").map(...)
